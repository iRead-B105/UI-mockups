# iRead 통합 기능 명세서

> 기준일: 2026-07-26  
> 대상: Vue 학습 앱, Vue 관리자 앱, Spring Backend, FastAPI/AI, Electron App  
> 서비스 성격: 난독증 아동의 읽기 학습 보조 서비스이며 의료 진단·치료 서비스가 아닙니다.

---

## 1. 사용자와 권한

| 사용자 | 앱 | 권한 |
|---|---|---|
| 아동 학습자 | 학습 앱 | 자신에게 배정된 테스트·훈련·이야기·성장 기록 사용 |
| 교수자·상담사 | 관리자 앱 | 자신에게 연결된 아동 조회·등록·수정·삭제, 커리큘럼 관리, 결과 조회, 보고서 생성 |
| 교수자·상담사 | 학습 앱 로그인 단계 | 교수자 인증 후 연결 아동 선택 및 학습자 세션 생성 |

### 필수 권한 규칙

- 클라이언트가 `teacherId`를 임의로 전달해 소유권을 결정하면 안 됩니다.
- 교수자 식별과 아동 소유 관계는 access token과 서버 데이터로 검증합니다.
- 학습 앱 access token은 선택된 아동 한 명의 범위로 제한합니다.
- 경로의 `studentId`와 토큰의 아동이 다르면 `403`을 반환합니다.
- 관리자 계정과 학습 앱 세션은 audience를 분리합니다.

## 2. 전체 시스템 흐름

```text
교수자 인증
  → 연결 아동 선택
  → 학습 앱 아동 세션 생성
  → Eye Tracker 상태/보정 확인
  → 메인
      ├─ 오늘의 학습
      │   └─ 훈련 안내 → 문항 수행 → 음성/시선 수집 → 완료
      ├─ 실력 확인
      │   └─ 테스트 안내 → 평가 문항 → 음성/시선 수집 → 완료
      ├─ 이야기 나라
      │   └─ 이야기 선택 → 읽기 → STT/TTS/시선 → AI 분기 → 완료
      └─ 나의 성장
          └─ 성장 지표·캐릭터 확인

관리자 로그인
  → 아동 선택
  → 학습 현황 / 훈련 이력 / 테스트 이력 / 커리큘럼 / 보고서
```

# 4. 학습 앱

## 4.1 로그인

### 목적

교수자가 먼저 인증한 뒤, 자신에게 연결된 아동을 선택해 학습 전용 세션을 생성합니다.

### 흐름

1. 교수자 아이디와 비밀번호 입력
2. 필수값 및 형식 검증
3. 학습 앱 교수자 인증
4. `teacherSessionToken`과 연결 아동 목록 수신
5. 대상 아동 선택
6. 아동 식별 및 교수자 연결 관계 검증
7. 학습 앱 access token 및 refresh cookie 생성
8. 아동 메인 화면 이동

### 완료 조건

- 선택된 `studentId`가 세션에 고정됩니다.
- 학습용 access token audience는 `learning-app` 계열로 제한합니다.
- refresh token은 HttpOnly, Secure, SameSite 정책을 적용합니다.
- 인증 실패와 연결 아동 식별 실패를 구분해 표시합니다.
- 연결된 아동이 0명이면 아동 선택 영역 대신 등록 안내와 로그아웃 버튼만 표시합니다.

### 관련 기능군

- `LG-TEA-*`: 교수자 입력, 검증, 인증, 성공·실패
- `LG-STU-*`: 연결 아동 조회, 선택, 아동 세션 생성
- `AU-APP-REF-*`: 토큰 갱신
- `AU-APP-OUT-*`: 로그아웃

## 4.2 메인

### 화면 요소

- 이야기 나라
- 오늘의 학습
- 실력 확인
- 학습 기록·나의 성장
- 캐릭터 인사말
- 공통 헤더

### 동작

- 메뉴 선택 시 각 도메인의 진입 화면으로 이동합니다.
- 진행 중 활동이 있으면 홈 이동 전에 이탈 확인을 표시합니다.
- 미저장 응답은 로컬 임시 저장 또는 서버 임시 저장 후 이동합니다.
- 캐릭터 인사말은 오늘의 배정 학습, 연속 학습, 미완료 활동을 기반으로 표시할 수 있습니다.

### 관련 기능

- `HM-01` 이야기 나라 이동
- `HM-02` 오늘의 학습 이동
- `HM-03` 실력 확인 이동
- `HM-04` 학습 기록 이동
- `HM-05` 캐릭터 인사말
- `HD-01~04` 프로필·홈 이동, 이탈 확인, 임시 저장

## 4.3 Eye Tracker 공통 처리

### 시작 전

1. 장치 연결 상태 확인
2. 장치명과 상태 표시
3. 상태 확인 중에는 헤더 상태등을 회색으로 표시
4. 아이트래커 보정은 외부 장치 프로그램에서 수행
5. 아동 UI는 별도 보정 기능 없이 필수 장치의 사용 가능 상태만 확인

### 수집 항목

- 콘텐츠 유형
- 활동·테스트·훈련·이야기 식별자
- 세션 시작·종료 시간
- 보정 상태
- 단어·문장 AOI별 체류 시간
- 고정 및 재고정 횟수
- 회귀 횟수
- 평균 응시 시간
- 장치 연결 끊김 및 수집 실패

### 실패 정책

- 시선 추적이 필수가 아닌 활동은 음성·선택 응답만으로 계속할 수 있습니다.
- 시선 추적 필수 활동은 아이트래커가 연결되지 않으면 시작을 막고 연결 안내 화면을 표시합니다.
- 시선 추적이 필수가 아닌 활동 도중 연결이 끊기면 학습은 계속하고 헤더 아이트래커 상태등을 빨간색으로 표시합니다.
- 마이크 필수 활동은 마이크가 없거나 권한이 거부되면 진행을 멈추고 `마이크를 켜 주세요` 안내 화면을 표시합니다.
- 마이크가 없거나 권한이 거부된 동안 헤더 마이크 상태등을 빨간색으로 표시합니다.
- 장치를 다시 연결하는 별도 버튼이나 설정 모달은 제공하지 않으며, 헤더 아이콘은 연결 상태 표시 전용으로 사용합니다.
- 장치 상태등은 사용 가능 초록, 현재 수집·녹음 중 파랑, 미연결·권한 없음 빨강, 확인 중 회색으로 표시합니다.
- 앱 시작 직후 장치 상태를 확인하는 동안에도 메인 진입은 허용하고 필수 장치 훈련 시작 시점에만 준비를 기다립니다.
- 필수 활동은 장치 연결 또는 권한 복구 후 다시 시작합니다.
- 실패 원인과 실패 시각을 저장합니다.
- 중복 세션을 생성하지 않도록 멱등성을 보장합니다.

### 관련 기능

- `GZ-GAZE-01` 장치 연결 상태
- `GZ-GAZE-02` 외부 보정 완료 상태 확인
- `GZ-GAZE-03` 실패 처리

## 4.4 훈련

### 지원 훈련 영역

- 음운 인식
- 글자와 소리 연결·파닉스
- 단어 해독
- 문장·짧은 글
- 유창성
- 긴 글 읽기

### 공통 흐름

1. 훈련 기본 정보 표시
2. 방법 안내
3. 훈련 세션 초기화
4. 세션 시작
5. 현재 문항 조회
6. 문항 유형에 맞는 단어·문장·이미지·음성·선택지 표시
7. 선택 응답 또는 음성 응답 수행
8. 시선 데이터 수집
9. 응답 검증·저장
10. 다음 문항 이동
11. 모든 문항 완료
12. 훈련 결과, 진행률, 성취율 저장
13. 개별 훈련 완료 화면 이동
14. `다음 훈련 시작`으로 오늘의 다음 순서 훈련을 바로 시작
15. 오늘의 마지막 훈련까지 끝나면 `오늘 학습 완료` 화면 이동

커리큘럼은 달력 날짜에 미리 고정하는 일일 시간표가 아니라 **다음 학습 회차** 단위로 생성합니다.
한 번 시작한 회차의 훈련 목록과 순서는 완료할 때까지 고정하며, 교수자의 변경 사항은 다음 회차부터 반영합니다.
훈련을 모두 마친 실제 날짜를 해당 회차의 학습일로 기록합니다.
배정 훈련이 0개인 회차는 오류가 아닌 휴식일로 처리하고 `오늘은 쉬는 날이야!` 화면을 표시합니다.
커리큘럼 생성 중에는 `오늘 학습을 준비하고 있어!` 대기 화면과 자동 재조회를 사용합니다.

### 문항 유형

| 유형 | 동작 |
|---|---|
| 듣고 고르기 | 문제 음성 재생 후 단일 선택 |
| 그림 고르기 | 단어·음성을 보고 대응 이미지 선택 |
| 보고 읽기 | 단어 또는 문장을 소리 내어 읽고 녹음 |
| 따라 읽기 | 예시 음성 재생 후 녹음 |
| 문장 읽기 | 목표 어절을 포함한 문장 읽기 |
| 유창성 읽기 | 제한 시간 내 글 읽기와 속도·정확도 측정 |

### 기능군

| 코드 | 역할 |
|---|---|
| `TR-INTRO-*` | 훈련 기본 정보 |
| `TR-GUIDE-*` | 방법 안내, 초기화, 시작 |
| `TR-DSP-*` | 단어·이미지·문장·목표 어절 표시 |
| `TR-SEL-*` | 선택지, 단일 선택, 정답 확인 |
| `TR-AUD-*` | 문제 음성 재생과 상태 제어 |
| `TR-REC-*` | 마이크 권한, 녹음, 파형, 검증, 저장 |
| `TR-GAZE-*` | 시선 수집 시작·종료·분석 저장 |
| `TR-COM-*` | 문항 조회, 진행률, 버튼, 이동 |
| `TR-SAVE-*` | 최종 저장, 입력 잠금, 성공·실패 |
| `TR-COMP-*` | 훈련 완료 |

### 완료 조건

- 필수 문항 응답이 모두 존재합니다.
- 음성 문항은 최소 녹음 시간과 음성 감지를 통과합니다.
- 저장 중 중복 입력을 막습니다.
- 동일 응답 재전송은 중복 로그를 생성하지 않습니다.
- 아동은 한 문항을 최대 3회 직접 시도하며, 이후 수동 버튼 없이 자동 시각 힌트를 제공합니다.
- 최초 오답, 재시도 횟수, 자동 힌트 사용 여부와 최종 성공 여부를 내부 학습 데이터에 저장합니다.
- 음성 미감지·STT 처리 실패는 발음 오답과 분리하며, 전자는 다시 말하기 안내만 표시하고 후자는 오답 및 시도 횟수로 기록합니다.
- 발음 합격 임계값은 서버 또는 훈련 템플릿이 관리하고 UI는 최종 `success`만 사용합니다.
- 정답 소리와 TTS는 횟수 제한 없이 재생할 수 있으며 재생 횟수는 내부 데이터에 기록합니다.
- 유창성 측정 시간은 서버에 기록하되 아동 화면에는 제한 시간이나 카운트다운을 표시하지 않습니다.
- 결과 저장은 로딩 화면 안에서 최대 2회 자동 재시도하고, 모두 실패한 경우에만 일반적인 오류와 재시도 동작을 표시합니다.
- 시선 수집 종료 실패가 전체 응답 저장을 롤백시키지 않도록 분리합니다.
- 훈련 완료 후 커리큘럼 진행률과 단어 누적 통계를 갱신합니다.
- 잠긴 미래 훈련을 누르면 이동하지 않고 기리 토끼가 `앞의 훈련부터 해보자!`라고 안내합니다.
- 개별 훈련 완료 화면의 기본 진행 버튼은 훈련 선택 화면이 아니라 다음 순서 훈련으로 연결합니다.
- 일일 커리큘럼 전체 완료 시 별도의 `오늘 학습 완료` 화면과 홈 이동 버튼을 표시합니다.
- 완료한 회차에 다시 진입하면 `오늘 학습 완료` 화면을 다시 표시합니다.
- 진행 중 훈련이 있으면 재접속 시 커리큘럼 지도의 현재 발판을 먼저 보여주고, 발판을 눌러 이어서 시작합니다.
- 비정상 종료 시 완료 문항까지만 복원하고 수행 중이던 문항은 처음부터 다시 시작합니다.
- 아동이 `그만하고 나가기`를 직접 선택한 훈련은 다음 진입 시 해당 훈련 처음부터 다시 시작합니다.
- 훈련 진행 중 뒤로가기, 아이리드 홈 로고 또는 로그아웃을 누르면 `학습을 그만할까요?` 확인 모달을 표시합니다.
- 이탈 확인 모달은 `계속 학습하기`, `그만하고 나가기` 두 선택지만 제공합니다.
- `계속 학습하기`를 누르면 현재 문항과 응답 상태를 그대로 유지합니다.
- 로그아웃 정보 삭제는 `그만하고 나가기`를 선택해 실제 화면 이동이 허용된 뒤 수행합니다.
- 앱 재접속 시 진행 중 훈련을 즉시 열지, 커리큘럼 지도에서 현재 위치를 먼저 보여줄지는 회의 후 확정합니다.
- 프로그램 비정상 종료에 대비한 서버 임시 저장은 ERD·API 저장 단위를 확정한 뒤 구현합니다.

## 4.5 테스트

### 목적

개인화 훈련 시작점과 주기적 변화를 확인하는 평가입니다.

### 훈련과의 차이

- 공통 평가 기준을 유지합니다.
- 결과는 개인화 커리큘럼의 입력으로 사용합니다.
- 테스트가 끝나기 전 세부 점수를 아동에게 노출하지 않습니다.

### 공통 흐름

3. 테스트 세션 초기화·시작

## 4.6 이야기 나라

### 흐름

1. 이야기 목록 조회
2. 카드와 진행 상태 표시
3. 신규 이야기 또는 이어보기 선택
4. 상세 정보 조회
5. 읽기 세션 생성 또는 재개
6. 조작 방법 안내
7. 장면·문장 표시
8. TTS 듣기 또는 아동 음성 읽기
9. 문장별 시선 수집
10. 장면 이동 및 진행 상태 저장
11. 분기 지점에서 아동 음성 입력
12. STT 텍스트와 현재 진행률로 AI 분기 생성
13. 생성 장면과 진행률을 트랜잭션으로 저장
14. 마지막 장면 완료
15. 엔딩에서 AI가 이야기 친구의 이름과 이미지를 생성
16. 친구 이름, 이미지, 출처 이야기 세션을 저장하고 책장·친구 보상에 반영

`새로운 책 읽기` 목록은 `story_templates`의 제목과 초기 표지 이미지를 사용합니다.
같은 원본으로 만든 여러 이야기는 동일 아동·동일 템플릿의 `stories.id` 오름차순으로 번호를 부여해 `1번째 이야기`, `2번째 이야기`처럼 구분합니다.
삭제된 이야기 상태도 순번 계산에는 포함하고 목록에서만 숨겨 기존 번호가 바뀌거나 재사용되지 않게 합니다.
읽는 중인 이야기가 여러 개면 `last_read_at`이 가장 최근인 이야기를 중앙의 `읽던 책 이어 읽기`에 표시합니다.
`last_read_at`이 아직 없으면 `created_at`이 가장 최근인 이야기를 우선하고, 페이지 읽기 완료 시 서버 시각으로 `last_read_at`을 갱신합니다.
완독한 이야기를 다시 읽어도 `last_read_at`을 갱신하며, `다른 책 읽기` 목록도 상태와 관계없이 최근 읽은 순서로 정렬합니다.
별도 `completed_at`은 추가하지 않습니다.

### 기능군

| 코드 | 역할 |
|---|---|
| `ST-LIB-*` | 목록, 카드, 진행 상태, 내 책장 |
| `ST-DTL-*` | 상세 조회, 신규 세션, 이어보기 |
| `ST-GUIDE-*` | 조작 안내 |
| `ST-READ-*` | 장면 조회·표시·이동·완료 |
| `ST-STT-*` | 음성 입력·인식·검증·저장 |
| `ST-TTS-*` | 본문 음성 생성·조회·재생 |
| `ST-GAZE-*` | 이야기 시선 수집·분석 |
| `ST-BRANCH-*` | 음성 분기, AI 생성, 저장 |

### AI 분기 규칙

- 클라이언트가 현재 진행률을 전달하지 않습니다.
- Backend가 `stories.progress`를 조회해 AI 요청에 포함합니다.
- AI가 반환한 다음 진행률은 현재값 이상, 100 이하인지 검증합니다.
- 신규 이야기 세션의 `stories.progress`는 0으로 생성하고 정수 범위 `0~100`만 저장합니다.
- 생성된 `story_lines` 저장과 `stories.progress` 갱신은 한 트랜잭션으로 처리합니다.
- 한 페이지를 처음 모두 읽으면 읽기 완료 API가 `story_lines.read_at`에 최초 완독 시각을 기록합니다.
- 같은 페이지를 다시 읽어도 `story_lines.read_at`은 유지하고 `stories.last_read_at`만 최신 서버 시각으로 갱신합니다.
- 읽기 완료 API는 중복 호출되어도 최초 또는 최신 정책에 따라 동일한 결과를 반환하도록 멱등하게 처리합니다.
- 진행률이 100이면 이야기 상태를 `COMPLETED`로 변경합니다.
- 생성 실패 시 기존 마지막 장면과 진행률은 유지합니다.
- 이야기 분기 생성은 서버 비동기 작업으로 계속되며, 화면 이탈·앱 종료 뒤에도 작업 ID로 상태와 결과를 복원합니다.
- 분기 생성 중에는 기리 토끼가 `다음 이야기를 만들고 있어!`라고 안내합니다.
- 숫자 진행률이나 예상 대기 시간은 표시하지 않고 단순 반복 애니메이션만 사용합니다.
- 다음 장의 본문과 배경 이미지가 모두 준비되고 저장된 뒤에만 읽기 화면으로 전환합니다. 본문만 먼저 노출하지 않습니다.
- STT가 정상 인식한 분기 답변은 별도 확인 화면 없이 바로 생성 요청에 사용합니다.
- 분기 질문에서 침묵이 길어지면 녹음을 종료하고 기리 토끼의 재시도 안내 뒤 자동으로 다시 녹음합니다.
- 본문은 아동이 직접 읽는 것을 기본으로 하고 읽기 실패 도움 상황에서만 TTS를 제공합니다.
- 서버는 최대 10회 분기와 현재 진행률을 기준으로 완결을 결정하며, 한 학습일에는 분기를 1회 진행합니다.
- 10번째 마지막 분기에서는 일반 다음 장 이미지 대신 엔딩 이미지를 생성하고, 저장 완료 후 별도 완독 축하 화면을 표시합니다.
- 이야기 분기에서 받은 아동 원본 음성은 `story_choices.audio_url`로 보관합니다.
- 아동 음성 파일의 서버 내부 경로를 API 응답에 노출하지 않습니다.

## 4.7 성장 기록·마이페이지

### 화면

- 고정 안내 캐릭터인 기리 토끼
- 획득 캐릭터 목록
- 영역별 성장 카드
- 성취 현황
- 성장률
- 영역별 시각 콘텐츠

### 성장 화단

- `파닉스`: 음운 인식과 파닉스 훈련 성취율을 함께 집계
- `읽기`: 짧은 글 영역 성취율 집계
- `유창성`: 유창성 영역 성취율 집계

### 완료 조건

- 서버 데이터가 없으면 0이 아닌 빈 상태를 명확히 표시합니다.
- 성장률 계산 기준 기간을 고정합니다.
- 각 화단은 영역별 누적 학습 횟수에 따라 흙·새싹·꽃봉오리·꽃·만개 5단계로 표시합니다. 성취율은 아동 화면에 표시하지 않습니다.
- 5단계별 누적 학습 횟수 임계값은 추후 확정합니다.
- 이전 방문보다 단계가 올랐다면 성장 화면 진입 시 해당 화단의 성장 애니메이션을 한 번 보여줍니다.
- 마지막으로 확인한 화단 단계는 EXE의 아동별 `localStorage`에 저장합니다.
- 만개한 화단을 누르면 기리 토끼가 `활짝 피었어!`라고 반응합니다.
- 안내·학습·반응 모션 캐릭터는 개발 비용과 모션 일관성을 위해 기리 토끼로 고정합니다.
- 획득 캐릭터는 이야기 친구 및 수집 목록으로만 사용하며 기리 토끼를 대체하지 않습니다.
- 이야기 친구는 생성된 이야기 결과에 따라 획득하므로 미획득 캐릭터 목록이나 잠금 실루엣을 미리 노출하지 않습니다.
- 획득한 이야기 친구가 0명이면 `이야기를 읽어서 친구를 모아봐요!` 빈 상태를 표시합니다.
- 획득 친구는 AI가 생성한 `name`, `imageUrl`과 친구를 만난 `storyId`를 함께 저장합니다.
- 같은 모습·이름의 친구가 다시 생성되더라도 이야기 세션별 별도 친구로 저장합니다.
- 친구 정보 저장 후 이미지 생성만 실패한 경우 `그림을 준비 중이에요` 공통 카드를 표시하고 서버에서 이미지 생성을 재시도합니다.

# 6. 멀티모달 분석

## 6.1 음성

### 저장

- 원본 음성
- 녹음 시작·종료 시각
- 문항·단어·문장 식별자
- STT 텍스트
- STT 신뢰도
- 발음 점수
- 읽기 오류 유형
- 재시도 횟수

### 오류 유형

- 대치
- 생략
- 삽입
- 반복
- 머뭇거림
- 자기 수정
- 음절 순서 오류

### 원칙

- 단일 오류로 취약 음운을 확정하지 않습니다.
- 목표 문장과 음성 시간축 정렬 결과를 함께 저장합니다.
- 내부 파일 경로를 외부 응답으로 반환하지 않습니다.

## 6.2 시선

### 분석 지표

- 총 체류 시간
- 평균 응시 시간
- 고정 횟수
- 재고정 횟수
- 회귀 횟수
- 단어·문장 건너뛰기
- AOI 이탈

### 원칙

- 시선만으로 해독·어휘·이해·주의 문제를 확정하지 않습니다.
- 음성 오류, 정답률, 단어 특성, 누적 수행을 함께 사용합니다.
- 관리자 화면에는 원시 좌표보다 요약 지표를 우선 표시합니다.

## 6.3 개인화

- 허용 어휘

# 7. 공통 예외 처리

| 상황 | 처리 |
|---|---|
| 네트워크 실패 | 현재 입력을 임시 저장하고 재시도 |
| access token 만료 | refresh 후 원 요청 1회 재시도 |
| refresh 실패 | 임시 저장 후 로그인 이동 |
| 마이크 권한 거부 | 설정 안내와 재요청 |
| 음성 미감지 | 재녹음 |
| Eye Tracker 미연결 | 대체 진행 또는 시작 차단 |
| 보정 실패 | 재보정 |
| 중복 제출 | idempotency key 또는 서버 중복 검증 |
| 저장 충돌 | `409 CONFLICT` |
| 다른 아동 접근 | `403 FORBIDDEN` |
| 없는 자원 | `404 NOT_FOUND` |
| 분석 지연 | `PENDING` 상태 표시 |
| 활동 이탈 | 미저장 데이터 확인 |
