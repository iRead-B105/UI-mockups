# iRead ERD·API 변경 이력

> 목적: UI 목업과 실제 데이터 구조를 비교하며 확정한 ERD·API 변경 사항과 결정 이유를 기록합니다.  
> 규칙: 이후 ERD 또는 API 계약을 변경할 때 이 문서를 같은 작업에서 함께 갱신합니다.

## 2026-07-26

### 적용 완료

| 대상 | 변경 내용 | 변경 이유 |
|---|---|---|
| `character` | `story_id`, `name` 추가 | 생성형 이야기의 결과로 얻은 친구 이름과 어떤 이야기에서 만났는지 저장하기 위해 |
| 이야기 친구 조회 API | `characterId`, `name`, `imageUrl`, `storyId`, `storyTitle`, `acquiredAt` 반환 | 친구 카드에 이름과 출처 이야기를 표시하기 위해 |
| 대표 캐릭터 API | 대표 캐릭터 변경 API 삭제 | 개발 비용을 줄이고 모든 안내·학습 모션을 기리 토끼로 고정하기로 결정 |
| `stories` | `progress INT NOT NULL DEFAULT 0` 추가 | 이야기 목록과 이어 읽기 화면에서 `0~100` 진행률을 표시하고 서버가 진행 상태를 관리하기 위해 |
| `story_templates` | `cover_image_url` 추가 | `새로운 책 읽기`에서 DB 초기 이야기의 표지를 표시하기 위해 |
| 이야기 세션 번호 | 동일 `student_id + story_templates_id` 안에서 `stories.id` 오름차순으로 `sessionNumber` 계산 | 같은 원본으로 생성한 여러 이야기를 새 AI 제목·표지 없이 구분하기 위해 |
| 이야기 세션 번호 삭제 정책 | `DELETED`도 순번 계산에는 포함하고 목록에서만 제외 | 기존 이야기 번호가 바뀌거나 재사용되는 것을 막기 위해 |
| `stories` | `last_read_at` 추가 | 여러 진행 중 이야기 중 가장 최근에 읽은 이야기를 중앙 이어 읽기 카드에 표시하기 위해 |
| 최근 이야기 정렬 | 읽는 중·완독 모두 `last_read_at DESC`, 값이 없으면 `created_at DESC` | 완독한 이야기를 다시 읽었을 때도 최근 목록 앞으로 이동시키기 위해 |
| `stories.completed_at` | 추가하지 않음 | 완독 시각보다 마지막으로 읽은 시각이 UI 정렬 목적에 더 적합하기 때문 |
| 페이지 읽기 완료 API | `PATCH /api/app/story/{studentId}/{storyId}/lines/{lineId}/read` 추가 | 최초 완독 시 `story_lines.read_at`을 기록하고, 재독할 때마다 `stories.last_read_at`을 갱신하기 위해 |
| `story_choices` | `audio_url` 추가 | 이야기 분기에서 받은 아동 원본 음성을 STT 문장과 함께 보관하기 위해 |
| 이야기 분기 응답 보안 | 원본 음성의 내부 저장 위치를 API 응답에서 제외 | 원본은 보관하되 아동 앱에 서버 내부 경로를 노출하지 않기 위해 |
| 이야기 템플릿 API 경로 | `/api/app/story/{studentId}/templates/{storyTemplateId}` 계열로 분리 | `{storyId}`와 `{storyTemplateId}`가 같은 경로 위치에서 충돌하는 문제를 해결하기 위해 |
| 이야기 엔딩 보상 | 분기 응답에 선택적 `awardedCharacter` 추가 | 엔딩에서 AI가 생성한 친구를 즉시 저장하고 UI에 반영하기 위해 |
| 이야기 친구 빈 상태 | 획득 친구가 0명이면 빈 배열과 `이야기를 읽어서 친구를 모아봐요!` 표시 | 생성 결과가 가변적이므로 미획득 캐릭터 목록이나 잠금 실루엣을 미리 만들 수 없기 때문 |
| 개별 훈련 완료 후 이동 | `다음 훈련 시작`으로 일일 커리큘럼의 다음 훈련을 바로 실행 | 아동이 별도 선택 없이 배정된 순서를 이어서 수행하게 하기 위해 |
| 일일 커리큘럼 완료 | 마지막 훈련 뒤 별도 `오늘 학습 완료` 화면 표시 | 하루 학습이 모두 끝났다는 종결감을 명확히 전달하기 위해 |
| 잠긴 훈련 선택 | 이동을 막고 기리 토끼가 `앞의 훈련부터 해보자!` 안내 | 순차 진행 규칙을 아동에게 짧고 친근하게 설명하기 위해 |
| 성장 화단 영역 | `파닉스`, `읽기`, `유창성` 3개로 구성하고 음운 인식은 파닉스에 합산 | 훈련의 4개 시각 그룹을 아동에게 더 단순한 3개 성장 영역으로 보여주기 위해 |
| 성장 화단 5단계 | 영역별 누적 학습 횟수를 흙부터 만개까지 5단계로 변환 | 성취율 증감으로 꽃이 시드는 표현을 피하고 학습 참여 자체를 긍정적으로 보여주기 위해. 단계별 횟수 임계값은 추후 확정 |
| 성장 단계 상승 연출 | 성장 화면 진입 시 이전 단계보다 성장했다면 애니메이션을 한 번 표시 | 학습 결과가 화단 성장으로 이어졌음을 아동이 즉시 인지하게 하기 위해 |
| 만개 화단 선택 | 기리 토끼가 `활짝 피었어!`라고 반응 | 더 성장하지 않는 상태에서도 클릭 피드백을 제공하기 위해 |
| 필수 시선 훈련 장치 없음 | 훈련 시작을 막고 아이트래커 연결 안내 표시 | 시선 데이터가 핵심인 훈련이 불완전한 상태로 진행되는 것을 막기 위해 |
| 선택적 시선 훈련 연결 해제 | 학습은 계속하고 헤더 시선 아이콘 상태등을 빨간색으로 표시 | 불필요하게 학습을 중단하지 않으면서 장치 상태는 명확히 알리기 위해 |
| 마이크 없음·권한 거부 | 음성 훈련을 멈추고 안내 화면과 헤더 빨간 상태등 표시 | 음성 입력이 불가능한 상태에서 아동이 반복 시도하는 것을 막기 위해 |
| 헤더 장치 아이콘 | 클릭 기능과 재연결 모달 없이 상태 표시 전용으로 사용 | 실제 장치는 케이블 연결 및 권한 상태로 복구되므로 중복 UI를 만들지 않기 위해 |
| 훈련 중 화면 이탈 | 뒤로가기·홈 로고·로그아웃에 동일한 `학습을 그만할까요?` 확인 모달 적용 | 아동의 실수로 진행 중 학습이 중단되는 것을 막기 위해 |
| 훈련 이탈 모달 선택지 | `계속 학습하기`, `그만하고 나가기`만 표시 | 난독 아동이 빠르게 선택할 수 있도록 설명과 선택지를 최소화하기 위해 |
| 로그아웃 시점 | 이탈 확인 후 실제 이동이 허용된 경우에만 인증 정보 삭제 | `계속 학습하기`를 선택했는데 세션이 먼저 삭제되는 모순을 막기 위해 |
| 이야기 분기 생성 대기 | 기리 토끼가 `다음 이야기를 만들고 있어!`라고 안내하고 숫자 진행률 없이 반복 모션 표시 | 생성 소요 시간을 부정확한 숫자로 약속하지 않으면서 아동이 현재 상태를 이해하게 하기 위해 |
| 생성 결과 노출 시점 | 다음 장 본문과 배경 이미지가 모두 준비된 뒤 읽기 화면으로 전환 | 글만 먼저 나타나거나 뒤늦게 배경이 바뀌는 불완전한 장면을 방지하기 위해 |

### 결정 대기

| 항목 | 현재 상태 | 확인할 내용 |
|---|---|---|
| `story_lines` 레코드 의미 | 회의 대기 | 한 레코드를 실제 한 줄로 볼지, 이미지 1장과 본문 2~3줄을 포함한 한 페이지·장면으로 볼지 결정 필요 |
| 학습 앱 이야기 응답의 `teacherId` | 회의 대기 | 아동 UI에서 사용하지 않고 `stories`에도 `teacher_id`가 없으므로 응답에서 제거할지 결정 필요 |
| `story_lines.has_choices`와 API `requiresBranchInput` 명칭 | 회의 대기 | 같은 의미의 필드명을 DB와 API에서 통일할지 결정 필요 |
| `stories.story_templates_id` 명칭 | 회의 대기 | API의 `storyTemplateId`와 맞춰 `story_template_id`로 변경할지 결정 필요 |
| 이야기 엔딩 축하 화면 구성 | 기획 대기 | 10번째 분기에서 엔딩 이미지를 생성하는 조건은 확정. 축하 화면에 표시할 제목·친구·재독·이동 버튼 구성은 추후 확정 |
| 만개 화단 상세 모달 | 기획 대기 | 만개 화단 클릭 시 토끼 반응에 더해 영역별 성장 상세 모달을 표시할지 추후 결정 |
| 성장 화단 단계별 학습 횟수 | 기획 대기 | 흙·새싹·꽃봉오리·꽃·만개로 바뀌는 누적 학습 횟수 임계값 확정 필요 |

## 2026-07-27

### 적용 완료

| 대상 | 변경 내용 | 변경 이유 |
|---|---|---|
| 학습 회차 생성 중 | `오늘 학습을 준비하고 있어!` 대기 화면과 자동 재조회 | AI 커리큘럼이 준비되기 전 빈 화면이나 오류로 오해하지 않게 하기 위해 |
| 훈련 0개 회차 | 오류가 아닌 휴식 상태로 처리하고 `오늘은 쉬는 날이야!` 표시 | 훈련이 배정되지 않은 날도 정상적인 학습 흐름으로 허용하기 위해 |
| 완료 회차 재진입 | `오늘 학습 완료` 화면을 다시 표시 | 이미 끝난 회차를 다시 시작 가능한 것처럼 보이지 않게 하기 위해 |
| 진행 중 훈련 재접속 | 커리큘럼 지도의 현재 발판을 먼저 보여주고 선택 시 복귀 | 즉시 문항 화면으로 진입하기 전에 아동이 현재 위치를 인지하게 하기 위해 |
| 비정상 종료 복구 | 완료 문항까지만 저장하고 수행 중 문항은 처음부터 재시작 | 중간 드래그·녹음 상태까지 복원하는 복잡성을 피하면서 완료 결과는 보존하기 위해 |
| 명시적 훈련 중단 | `그만하고 나가기`를 고르면 해당 훈련을 처음부터 재시작 | 아동이 의도적으로 종료한 세션과 갑작스러운 종료를 구분하기 위해 |
| 학습 회차 변경 | 시작한 회차는 고정하고 교수자 변경은 다음 회차부터 반영 | 진행 중 순서가 갑자기 바뀌는 것을 막기 위해 |
| 학습일 의미 | 사전 날짜가 아니라 회차를 실제 완료한 날짜 사용 | 서비스가 달력형 일정보다 다음 회차 학습을 생성하는 구조이기 때문 |
| 문항 재시도 | 최대 3회 직접 시도 후 수동 버튼 없는 자동 시각 힌트 제공 | 자잘한 UI를 줄이면서 아동이 스스로 시도할 기회를 보장하기 위해 |
| 훈련 시도 데이터 | 최초 오답, 시도 횟수, 힌트 사용, 최종 성공을 모두 저장 | 개인화 학습 자료 생성과 오류 패턴 분석에 사용하기 위해 |
| 음성 실패 분리 | 미감지·STT 실패는 재시도 안내, 목표 발음 불일치는 오답 처리 | 장치·인식 실패를 아동의 학습 실패로 기록하지 않기 위해 |
| 발음 성공 판정 | 서버·템플릿이 임계값을 관리하고 UI는 `success`만 사용 | 판정 정책이 바뀌어도 아동 UI 로직을 수정하지 않기 위해 |
| 유창성 시간 | 아동에게 제한 시간을 표시하지 않고 서버 측정값만 기록 | 시간 압박을 줄이면서 읽기 속도 데이터는 수집하기 위해 |
| TTS 재생 | 횟수 제한 없이 허용하고 재생 횟수만 기록 | 필요한 만큼 다시 듣게 하면서 도움 요청 정도를 학습 데이터로 남기기 위해 |
| 결과 저장 실패 | 로딩 중 최대 2회 자동 재시도 후 일반 오류만 표시 | 저장 기술 용어를 아동에게 노출하지 않기 위해 |
| 완독 이야기 재독 | 처음부터 읽기와 재독 중 이어 읽기를 모두 제공 | 긴 책을 반복해서 읽을 때 매번 처음부터 강제하지 않기 위해 |
| 이야기 비동기 생성 | `story_generation_jobs`와 작업 상태 조회 API 추가 | 화면 이탈·앱 종료 뒤에도 서버 생성을 계속하고 결과를 복원하기 위해 |
| 이야기 STT 확인 | 정상 인식 문장을 별도 확인하지 않고 즉시 생성 요청 | MVP 흐름과 선택 요소를 단순화하기 위해 |
| 이야기 침묵 처리 | 자동 녹음 종료, 토끼 안내, 자동 녹음 재시작 | 수동 마이크 조작 없이 다시 대답하게 하기 위해 |
| 이야기 도움 TTS | 직접 읽기가 기본이며 읽기 실패 도움 상황에서만 재생 | 시선·읽기 데이터를 보존하면서 막힌 아동을 지원하기 위해 |
| 이야기 완결 | 하루 1회 분기, 최대 10회, 10번째에는 엔딩 이미지 생성 | 약 10일간 이어 읽는 생성형 이야기의 종료 조건을 서버가 안정적으로 관리하기 위해 |
| 친구 중복 | 같은 친구처럼 보여도 이야기 세션별 별도 저장 | 생성 결과의 동일성 판정이 불안정하고 출처 이야기를 보존해야 하기 위해 |
| 친구 이미지 실패 | `image_status`를 저장하고 준비 중 카드 표시 후 재시도 | 텍스트 친구 정보까지 잃지 않으면서 이미지 생성 실패를 복구하기 위해 |
| 장치 상태 | 초록 사용 가능, 파랑 사용 중, 빨강 미연결, 회색 확인 중 | 헤더의 상태 의미를 모든 화면에서 통일하기 위해 |
| 아이트래커 보정 | 아동 UI 보정 기능 제거, 외부 장치 프로그램이 담당 | 장치 제어 책임을 중복 구현하지 않기 위해 |
| 성장 기준 | 성취율 대신 영역별 누적 학습 횟수로 화단 성장 | 성취율 하락과 관계없이 학습 참여가 쌓이는 긍정적 표현을 사용하기 위해 |
| 성장 애니메이션 확인값 | 아동별 마지막 확인 단계를 EXE `localStorage`에 저장 | 같은 단계의 성장 애니메이션이 진입 때마다 반복되지 않게 하기 위해 |
